# TypeScript 作为布局与错误码的单一真相源

`qf_value` 的 24 字节、`qf_node` 的 56 字节、每个字段的偏移，以及全部错误码与算子编码，都只在 `schema/qf.ts` 声明一次，由 `codegen/gen.ts` 生成 C/C#/Python 绑定，C 侧再用 `_Static_assert` 钉住尺寸。手写多份一致的布局是不可能的任务，而漂移的症状是随机读到垃圾数据，而不是编译失败——这类 bug 的定位成本远高于维护一个生成器。

## 考虑的方案

- **以 C 头文件为准，其它语言手写**：改动契约时需要人工同步 4 处，必然漂移。
- **用 IDL（protobuf/flatbuffers）生成**：引入第三方工具链，且需要表达的只是固定偏移，收益不足。

## 后果

构建必须先跑 codegen；生成物入库，保证每个语言提交都能独立编译。新增一种语言时，只需在 `codegen/gen.ts` 增加一个 emitter。
